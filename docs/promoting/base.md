我是一名独立开发者，我凭着自己的兴趣与需求出发开发产品，打算今年做五十个产品，这是今年第七个产品。

这个产品的需求背景是，在我们开发一些软件产品时，经常需要配置 .env 文件，而且前端与后端、开发模式与生产模式、本地与服务器端都不一样（环境变量的多值管理是个很不省心的活）；甚至不同的框架的需求也不一样（比如 nextjs 框架要求暴露在前端的环境变量需要以 NEXT_PUBLIC_ 开头，而 vite 则需要以 VITE_ 开头）；另外，很多服务厂商的秘钥只允许生成一次，往往被复制在了某个项目的.env里，又由于避免暴露公网的原因被 git ignore 从而漏在了某个磁盘文件夹里，事后根本找不到，这是一件更头疼的事。

基于上述的这些痛点，我才开发了这样一种中心化、原子化配置各平台环境变量，并以项目级别配置输出.env文件的管理系统。它支持一个独立的前端、一个独立的后端，一个独立的命令行工具，用户可以直接访问我们的公网前端进行登录，并配置 key 和项目，最后直接导出，或者基于命令行工具直接拉取配置生成项目级别的 .env 文件。这是整个项目架构的构想。

期间我使用 windsurf + claude-3.5-sonnet + chatgept-o3-mini + deepseek-r1 混合开发完成，耗时 2 天，并不断维护中。如果对该产品感兴趣，可以联系后台申请加付费产品群，主要以 C 端为主（目前D端较多），年价 99 元（限时）。

本产品的体验地址：https://keybox.cs-magic.cn。命令行登录模式是PKCE，相对安全；而秘钥等信息入库，就我们的用户协议和隐私协议，我们会承诺不会侵犯用户的数据安全，否则可提起法律申诉。如果实在担心各种风险，推荐私有化部署，代码开源在：https://github.com/MarkShawn2020/2025-02-04_keybox
